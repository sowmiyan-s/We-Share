Frequently Asked Questions

Everything you need to know about We Share. Can't find your answer? Open an issue on GitHub.

General
We Share is an open-source local file sharing utility written in C# (.NET 8) and styled with Avalonia UI. It sends files directly over local network sockets (TCP) without using any cloud relays or third-party web servers.
Yes. The project is licensed under the MIT License and the source code is entirely public. There are no subscriptions, ads, or tracking.
No. It operates entirely on your local area network (LAN/WLAN). If your router doesn't have an active internet link, or even if you don't have a router at all, the application will still function.
No. We Share requires no registration, logins, or configuration. It runs locally as a self-contained program.
Compatibility
The native desktop client runs on Windows 10 (build 19041+) and Windows 11. Other operating systems (macOS, Linux, iOS, Android) can send and receive files by accessing the host's Web Portal via any standard browser.
Yes. Start the app on your computer, note the web address displayed (which points to the app's local port 8080), and navigate to it on your phone's browser. You can then download shared files or upload photos and documents directly to your PC.
No. Files are streamed directly between devices, meaning there are no arbitrary size limits or format restrictions. Transfers are limited only by your disk space and network interface card.
Features
If there is no active local network, We Share initializes an ad-hoc Wi-Fi hotspot in the background using Windows Mobile Hotspot APIs. The client device detects this specific SSID and establishes a handshake connection automatically, allowing offline local transfers without manual configuration.
We Share uses UDP socket broadcasting. It regularly sends discovery packets on a dedicated local subnet port. Other instances running on the same subnet listen to these broadcasts, parse the sender information, and list the active peers in the visual radar.
Yes. Every transfer request is parsed and prompts the receiver with the sender's hostname, file listing, and total payload size. Files will not be written to disk until you explicitly click Accept.
Yes. A history database is managed locally via an offline SQLite file stored in the app data directory. This database remains entirely on your machine and is never shared or exported.
Privacy & Security
Yes. All socket connections are established peer-to-peer on your local subnet. No telemetry, third-party analytics, or external trackers are compiled into the application.
Yes. Since We Share relies on local TCP and UDP sockets for network communication, Windows Firewall must be configured to allow this traffic on your local subnet. The installer automatically registers these rules for the application executable, and they are fully removed when you uninstall.
Troubleshooting
  • ▸ Verify that both devices are connected to the same local subnet.
  • ▸ On public or corporate networks, access point isolation (AP isolation) is often enabled, which blocks UDP broadcasts and peer communication.
  • ▸ Check that your Windows Firewall allows UDP traffic on the radar discovery ports.
  • ▸ If no wireless router is available, ensure you use the ad-hoc Desert Mode.
We Share does not throttle bandwidth and streams files as fast as your hardware allows. For maximum throughput, connect via a wired gigabit Ethernet cable, or ensure your devices are close to a high-speed Wi-Fi 5/6 router with clear line of sight.
